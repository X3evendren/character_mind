# ADR-016 意识流中断重组机制

**状态**：proposed

回复生成期间（L5, 可配置模型, 默认Pro, 3-8s），意识流（L4, 可配置模型, 默认Pro, 5s tick）在后台并行运行。当意识流产生权重超过阈值的强念头时，中断当前生成（AbortController），将新念头注入 prompt，重新开始生成。被中断的 token 丢弃，中断事件记录为"自我修正"记忆。

**为什么**：人类在说话时不是"想好全部→一次性输出"。我们是边说边想——说了一半意识到自己刚才的理解有误、或突然想起一个重要的关联、或注意到对方的微表情改变了。这个过程不是缺陷，而是人类对话流畅性的一部分。"等等，我刚想起来..."比"我完美地说完了预先想好的话"更真实。

技术代价：中断后重新生成意味着已输出的 token 被浪费（API 调用的 token 已消耗），且用户看到的前几个词/句子可能被"回滚"——"我今天觉得..."被中断，变成"等等，我刚想起来...今天其实..."。在 UI 层，这需要处理：要么回滚已显示的文本（体验差），要么让角色自然过渡——"我今天觉得...不，等等，我刚想起来..."（体验好但需要 prompt 设计让第二段生成承接第一段的碎片）。

**代价**：API token 浪费（每次中断约 20-200 tokens）。频繁中断会破坏阅读体验。需要仔细设计权重阈值——太低了频繁中断，太高了不会中断。中断后的 prompt 构建需要包含第一段的碎片文本 + 新念头 + 原始用户输入 + 完整上下文，prompt 更长。

**备选方案**：（1）意识流只在沉默期运行——简单但丧失了"边说边想"的人类特征。（2）意识流的念头记录下来，下一轮自然提及——不打断当前回复，但错过了最佳时机。（3）预先生成完整回复，让意识流在生成前跑完——失去了实时性，且意识流本身是由生成过程中的记忆激活驱动的。
