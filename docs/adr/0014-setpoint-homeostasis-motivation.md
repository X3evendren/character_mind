# ADR-014 设定点 + 负反馈稳态动机

**状态**：proposed

用设定点 + 负反馈回路的稳态架构替换当前的固定驱力衰减回归模型。每个稳态变量有一个设定点（初始来自角色配置，交互中动态漂移），偏离设定点产生对应动机，满足后回归。设定点本身随长期交互漂移。

**为什么**：当前 5 个驱力有初始值、有衰减、有 `_tick()` 的定时回归——但没有"满足"的概念。角色的"连接驱力"是 0.3 还是 0.7，唯一的影响是 `DriveSublimator.buildStyleHints()` 输出不同的温度偏移——这只是一个风格调制器。用户对角色说"我想你"、角色帮助用户解决了一个大问题、用户认可了角色的能力，这些事件**对驱力没有任何影响**。

在设定点架构中，每个稳态变量持续感知交互事件对它的影响：连接变量在用户表达亲近时得到满足（回归设定点），在用户冷淡/离开时产生偏离。偏离产生真正的行为驱动力——不只是"语气更友好"，而是"主动发起对话""提出更深的问题""表达担忧"。更重要的是，设定点的漂移解释了人格的形成——长期被满足的连接需求导致设定点升高（角色需要更多连接才能感到满足），这是一种依赖的形成；长期被剥夺导致设定点降低（角色适应了孤独），这是一种防御。

规避动机（BIS）在这里获得独立的存在——它不是趋近动机（BAS）的反面。威胁检测（安全的偏离）产生规避行为，与趋近行为并行运行。角色可以"想接近但害怕受伤"——高 BAS 连接 + 高 BIS 威胁同时存在。

**代价**：需要定义稳态变量的种类（初始建议：连接/安全/掌控/能量/新奇，可配置扩展）。需要为每个交互事件定义它对各稳态变量的影响方向和幅度（需要 LLM 做语义理解还是规则匹配？初始建议规则匹配 + 关键事件 LLM）。设定点的漂移速率需要设计——太快会导致不稳定人格，太慢则没有适应性。

**备选方案**：给现有驱力加"满足"回调——事件触发驱力更新。但这不能解决根本问题：驱力是固定的 5 种，缺乏规避维度，没有设定点漂移。只是给旧系统打补丁。
